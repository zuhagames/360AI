360AI 1.2 - Xbox 360 USB package
================================

INSTALL
1. Extract the ZIP on your PC.
2. Copy the entire 360AI folder to your USB drive.
3. Gemma 3 270M and SmolLM2 135M Q8_0 models are included beside 360AI.xex.
   No separate download is needed for these models.
4. Safely eject the USB, connect it to your modded Xbox 360, and open
   the 360AI folder with your existing XEX launcher (Aurora/XEXMenu).
5. Launch 360AI.xex, select either included GGUF and choose Load model.
   Leave Compute backend and Weight storage on Auto. Auto selects RAM
   when the model and working memory fit, and benchmarks CPU/GPU.
   SmolLM2 135M is a good starting point for responsive local chat.

Example USB layout:
  USB:/360AI/360AI.xex
  USB:/360AI/gemma-3-270m-it-Q8_0.gguf
  USB:/360AI/SmolLM2-135M-Instruct-Q8_0.gguf
  USB:/360AI/START_HERE.txt
  USB:/360AI/CHANGELOG.txt
  USB:/360AI/CREDITS.txt

The folder can also be copied to your Xbox HDD. Keep the GGUF beside
the executable. No SDK, Visual Studio, Node.js or separate shader files
are needed on the console. The app does not install or replace a dashboard.

BUNDLED MODELS
The full Gemma 3 270M Instruct Q8_0 GGUF is included (about 292 MB).
Read NOTICE, GEMMA_TERMS.txt and GEMMA_POLICY.txt for its terms, and
MODEL_INFO.txt for its source and checksum. No account or network is
needed for local console chat once this ZIP is downloaded.
SmolLM2 135M Instruct Q8_0 is also included (about 145 MB). It uses less
weight memory. See SMOLLM2_INFO.txt and APACHE-2.0.txt for its source/license.

Read MODELS.txt for optional Qwen models and their HDD space requirements.
Download-Models.ps1 runs on your Windows PC and verifies pinned checksums.
For larger models choose Weight storage: HDD/USB stream. Matrix weights stay
on disk with an 8 MB cache; tokenizer/scratch/KV buffers still use RAM.
Keep all split GGUF files together and select the first shard. The browser
shows their total storage requirement. Large models can be extremely slow.
Start with context 256-512. This app requires unsigned-XEX support.

PERFORMANCE
Compute backend Auto uses a short CPU/GPU numerical and timing comparison.
GPU math uses Xenos pixel shaders; Auto keeps it only when the sample is
correct and at least 20% faster. Forced GPU remains experimental.
The chat footer and 360AI.log show which backend/storage were selected.
Matching conversation history is reused. Prompt progress and elapsed time
are displayed while processing; tokens/second measures generation itself.
Console replies default to 128 tokens; change Reply token limit if needed.
Xbox speed and full GPU correctness still need physical-console testing.

NEW CHAT CONTROLS AND SAVED SETTINGS
X: start a new conversation without reloading the model (when idle).
START: save the current conversation to 360AI-chat.txt (when idle).
Y: stop a running console reply. B: return to the model list.
Saving a conversation replaces the previous export; nothing is exported
automatically. The model and weight files stay loaded for a new chat.
If an API request is running, new chat reports busy instead of waiting.

Settings are remembered in 360AI.json beside the executable, including
context, sampling, reply limit, logging and chat/server/backend/storage.
A previous valid copy is kept in 360AI.json.bak for recovery. These files
are not bundled in updates. Remove both files to restore defaults.
The app folder must be writable to save settings and conversations.

OPTIONAL OPENAI / MCP SERVER
Turn OpenAI / MCP server ON before loading the model. Use the IP and
port displayed on the console; the default port is 80, then 8080.
Open http://CONSOLE-IP:PORT/health to check connectivity.
OpenAI client base URL: http://CONSOLE-IP:PORT/v1
Generation endpoints require POST with JSON, not browser navigation.
The server is for your private LAN; it has no authentication.

Requests support temperature, top_k, max_tokens/max_completion_tokens,
stop strings and streaming usage. Stop strings can span multiple tokens.
Responses include token usage and timings, and distinguish stop/length.
For streaming usage add stream_options: {"include_usage": true}.
Developer-role text messages map to system messages for local templates.

External MCP stdio/HTTPS servers use the bridge source from the project's
GitHub repository on a PC. See docs/TECHNICAL.md in the repository for setup.
Local console chat does not need the bridge or any PC software.
